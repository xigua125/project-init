# V1.1.4 Validator Procedure V1.1 — Portability Amendment

Status: CANDIDATE — SUBORDINATE TO EXECUTION CONTRACT V1.3 + V1.4 PORTABILITY AMENDMENT

This amendment incorporates Validator Procedure V1.0 and changes only its identity, custody, and write-exclusion interpretation. All other V1.0 requirements remain unchanged.

1. Treat write authority as the role-scoped authorized write set, never as a synonym for OS permissions.
2. Resolve `validator_logical_identity` and `builder_logical_identity` to recorded logical identity hashes and agent-instance identifiers. Reject equal agent-instance identifiers. Do not reject distinct instances merely because `os_identity_relationship=SAME`.
3. Verify custody from the non-Builder producer/approver role and logical identity, canonical byte/self hashes, referenced evidence hashes, an authorizing anchor timestamp before the governed BUILD/stage, an append-only evidence-chain/head verification, equal protected-location before/after snapshot hashes, and `final_auditor_reverification_required=true`.
4. Reject Builder-produced or Builder-approved external anchors regardless of directory. Reject post-BUILD authorizing anchors under RT-37; they cannot be repaired by changing role labels or moving files.
5. Record `assurance_profile=HIGH_ASSURANCE` only when an OS/mount/sandbox/equivalent isolation mechanism is verified. Otherwise record `PORTABLE_DEFAULT` and `high_assurance_isolation=false`. This absence alone is not a failure.
6. Final Auditor re-verifies logical identities and agent instances, authorized write sets, all bound bytes/hashes, authorization timing, evidence records and anchor chain, and protected-location before/after snapshots.
7. The before/after guarded path applies to the audited root and every protected external control-plane/anchor location used by the result. Any diff is a write/protection violation using the existing error vocabulary.

Procedure version emitted by updated tooling is `v1.1.4-validator-procedure/1.1`. Existing V1.0 results remain historical; they are not rewritten or upgraded.
