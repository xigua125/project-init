# V1.1.4 Targeted Clarification Proposal

Status: CANDIDATE — INDEPENDENT REVIEW REQUIRED

Basis: V1.1.3, Execution Contract V1.2, the Mac-Mini-AI-Employee Stage 0 independent audit, and the subsequent Codex forensic review.

Purpose: evolve the existing V1.1.3 Skill in place. Preserve V1.1.3 behavior except where clarification is required to close control-plane placement, self-reference, anchor-role, and post-freeze ordering gaps.

## Confirmed gaps addressed

1. Canonical control-plane artifact placement was not closed across SKILL and Execution Contract.
2. In-root registries/manifests could induce self-registration or self-hash ambiguity.
3. Pre-BUILD approval, registry approval, freeze-hash, and evidence-chain-head anchors were not sufficiently distinguished.
4. Final inventory/status wording could be read as permitting post-freeze writes into the audited root.
5. Missing pre-BUILD Human authorization was not stated strongly enough as non-retroactive.
6. Write authority, independent custody, and identity separation could be misread as requiring OS-account/ACL isolation, making otherwise valid logical role separation non-portable.

## Preserved rules

- Builder/Auditor separation remains mandatory.
- Builder-created files cannot satisfy independent-anchor authority.
- Origin Registry fields including mode and symlink_target remain mandatory.
- If INDEPENDENT_REVIEW != PASS, PROJECT_INIT_STATUS remains PENDING_INDEPENDENT_REVIEW and READY_FOR_IMPLEMENTATION remains NO.
- V1.1.3 historical evidence is not rewritten.
- Failed Mac mini lineage is not retroactively converted to PASS.
- V1.1.4 is Candidate until independent audit and regression validation succeed.

## V1.1.4 clarification

Canonical pre-BUILD specs/registries and Freeze/evidence control-plane artifacts are external to the audited root. Freeze Manifest is generated from Snapshot B after Snapshot B and therefore never contains itself. Independent anchors are separated by role and remain outside Builder write authority. Post-freeze status/audit updates remain external; any required audited-root mutation invalidates the freeze and starts a new freeze sequence.

Execution Contract V1.4 defines write authority as a logical role/authorized-write-set boundary and identity as a logical agent-instance record. Portable custody uses non-Builder role separation, recorded logical identity, hash-bound immutable bytes, pre-BUILD timing, append-only chain plus protected-location before/after guards, and Final-Auditor replay. OS-level isolation is optional preferred high-assurance evidence, not a default PASS prerequisite.

## Required regression additions

- Placement: canonical registries and Freeze Manifest are outside audited root.
- Self-reference: no canonical control-plane artifact is required to register/hash itself.
- Anchor roles: pre-BUILD, registry, freeze-hash, and evidence-chain-head anchors cannot silently substitute for one another.
- Authority: Builder cannot satisfy independent-anchor authority merely by choosing an external path.
- Post-freeze: audited-root status/manifest write invalidates Freeze.
- State machine: PENDING independent review cannot coexist with final PROJECT_INIT_STATUS=PASS.
- Missing pre-BUILD approval: BUILD without a verified Human pre-BUILD anchor stays unauthorized; later anchors cannot legalize it.
- Integrated cross-case: RT-38 must jointly exercise the V1.1.4 control-plane rules in one execution.
- Portability: same OS identity with distinct logical role instances can PASS; the same Builder/Validator agent instance fails; Builder-authored external and post-BUILD anchors fail; absence of OS isolation records non-high-assurance without blocking; protected-location writes are detected; existing tamper/chain-head negatives remain failures.

## Migration

V1.1.3 remains immutable historical evidence. V1.1.4 Candidate begins a new validation lineage. Counter carry-forward is explicit: remediation_loops, validation_cycles, and production_validation_cycles carry forward unchanged from the applicable predecessor lineage unless a Human-approved Contract Change record explicitly states otherwise; no counter resets merely because of version rename or re-freeze. Mac-Mini-AI-Employee remains untouched during Skill repair; its next Stage 0 validation must use a new authorization lineage after V1.1.4 is independently accepted.
